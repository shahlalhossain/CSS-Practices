Responsive Web Design

Responsive Web Design (RWD) means building a page so it looks good and stays easy to use on any device — desktop, tablet, or phone — rather than building a separate fixed-width page for each. Instead of the browser scaling a fixed layout up or down (which just makes everything tiny or forces horizontal scrolling), a responsive page's HTML and CSS actively resize, hide, shrink, stack, or enlarge its own content to fit whatever viewport it's loaded into.

Why RWD Matters

Before smartphones and tablets were common, most websites were designed for one screen size. Browsing a desktop-only site on a phone meant either a tiny unreadable layout or constant pinch-zooming and sideways scrolling. As mobile browsing overtook desktop, designing pages that adapt to the viewport stopped being optional — it's now the baseline expectation for any public-facing page.

The Three Core Techniques

RWD isn't one single CSS property — it's a combination of three techniques working together, each covered in its own lesson later in this CSS Responsive section:

  • The viewport <meta> tag — without it, mobile browsers render the page at a fixed desktop-like width and then zoom it out to fit, which defeats every other responsive technique before it even runs. Covered in RWD Viewport.
  • A flexible layout — sizing containers with relative units (percentages, fr, %-based grids) via grid or flex instead of fixed pixel widths, so the layout itself can grow and shrink. Covered in RWD Grid View.
  • Media queries — CSS rules that only apply once the viewport matches a given condition (most often a width breakpoint), letting a layout restructure itself rather than just resize proportionally. Introduced generally back in CSS Media Queries, and covered here with full responsive breakpoint examples in RWD Media Queries.

A fourth concern, flexible images (keeping images from overflowing their container as it shrinks), is covered separately in RWD Images.

A Minimal Responsive Example

To make the idea concrete before the dedicated lessons, here's a single box that restyles itself once the viewport narrows past 600px — the same media-query mechanism that powers every responsive technique in this section, just applied to one element instead of a whole layout.

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <meta name="viewport" content="width=device-width, initial-scale=1.0">
     <style>
         .box {
             background-color: dodgerblue;
             color: white;
             text-align: center;
             padding: 40px;
             font-size: 24px;
         }

         /* On narrow viewports, swap colors and shrink the text */
         @media screen and (max-width: 600px) {
             .box {
                 background-color: tomato;
                 font-size: 16px;
             }
         }
     </style>
</head>
<body>

     <div class="box">Resize the browser window</div>

</body>
</html>

At 600px or narrower, it turns red with smaller text (simulated here in a fixed-width box):

Note: The @media screen and (max-width: 600px) rule above is real, working CSS, and the viewport meta tag shown is the same one every page in this site already includes in its own <head>. Because the query reads the actual browser viewport rather than a table cell, you'd need to shrink the whole browser window below 600px to see it fire here; the second box simulates that narrow state inside a fixed-width wrapper, the same approach used in the Flexbox Responsive lesson.
