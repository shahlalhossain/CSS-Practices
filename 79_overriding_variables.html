CSS Overriding Variables

Because a CSS variable follows the normal cascade, a local variable declared inside a more specific selector overrides a global one declared on :root, but only within the scope of that selector and its descendants — everywhere else on the page still sees the original global value.

Override Global Variable With Local Variable

Here, --primary-bg-color is declared globally on :root as blue. Inside .container .note, the same variable name is redeclared as red — so any var(--primary-bg-color) used inside that one element (and its children) resolves to red, while the rest of the page is unaffected and stays blue.

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         :root {
             --primary-bg-color: #1e90ff;
             --primary-color: #ffffff;
         }
         body {
             background-color: var(--primary-bg-color);
         }
         .container {
             color: var(--primary-bg-color);
             background-color: var(--primary-color);
             padding: 15px;
         }
         .container h2 {
             border-bottom: 2px solid var(--primary-bg-color);
         }
         .container .note {
             --primary-bg-color: red; /* local variable will override global */
             border: 1px solid var(--primary-bg-color);
             padding: 10px;
         }
     </style>
</head>
<body>

     <h1>Override Global Variable With Local Variable</h1>

     <div class="container">
         <h2>Lorem Ipsum</h2>
         <p>Lorem ipsum dolor sit amet, consectetur adipiscing elit. Etiam semper diam at erat pulvinar, at pulvinar felis blandit.</p>
         <p>Lorem ipsum dolor sit amet, consectetur adipiscing elit. Etiam semper diam at erat pulvinar, at pulvinar felis blandit.</p>
         <p class="note">This is a note!</p>
     </div>

</body>
</html>

Note: Look closely at the heading's underline and the "This is a note!" box: the heading's border-bottom is still blue because it sits in .container, outside .container .note's scope — but the note box's own border is red, because the local redeclaration of --primary-bg-color only reaches var() calls made inside .container .note itself.

Add a New Local Variable

A local variable does not have to share a name with an existing global one — it can introduce a brand-new variable that only exists inside its own selector. Here, .container .note declares a new variable, --note-border-color, used only for that element's border; no other selector on the page can reference it.

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         :root {
             --primary-bg-color: #1e90ff;
             --primary-color: #ffffff;
         }
         body {
             background-color: var(--primary-bg-color);
         }
         .container {
             color: var(--primary-bg-color);
             background-color: var(--primary-color);
             padding: 15px;
         }
         .container h2 {
             border-bottom: 2px solid var(--primary-bg-color);
         }
         .container .note {
             --note-border-color: red;
             border: 1px solid var(--note-border-color);
             padding: 10px;
         }
     </style>
</head>
<body>

     <h1>Add a New Local Variable</h1>

     <div class="container">
         <h2>Lorem Ipsum</h2>
         <p>Lorem ipsum dolor sit amet, consectetur adipiscing elit. Etiam semper diam at erat pulvinar, at pulvinar felis blandit.</p>
         <p>Lorem ipsum dolor sit amet, consectetur adipiscing elit. Etiam semper diam at erat pulvinar, at pulvinar felis blandit.</p>
         <p class="note">This is a note!</p>
     </div>

</body>
</html>

Note: The visual result here looks identical to the previous example, but the mechanism is different: this time --primary-bg-color was never touched inside .note, and a brand-new variable name was introduced instead purely for that one border. Both approaches are valid; which to use depends on whether you're overriding an existing themed value or introducing a value that's genuinely local to one component.
