RWD Viewport

The viewport is the visible area of a web page on the user's device — much smaller on a phone than on a desktop monitor. Before mobile browsers understood responsive pages, they simply rendered a page at a fixed desktop-like width (around 980px) and then zoomed the whole thing out to fit the screen, forcing visitors to pinch-zoom and scroll sideways to read anything. Every technique in this CSS Responsive section depends on first telling the mobile browser to stop doing that.

This is some text on a web page. Without the viewport meta tag, mobile browsers render at a wide fixed layout and zoom it out, so it all looks tiny.

Left: no viewport meta tag (rendered wide, then shrunk). Right: with the viewport meta tag (rendered at the device's own width).

Setting the Viewport

HTML5 introduced a way to let web authors take control of the viewport through a <meta> tag placed inside <head>:

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <meta name="viewport" content="width=device-width, initial-scale=1.0">
</head>
<body>

     <h2>Hello World!</h2>
     <p>This text and viewport will resize with the device width.</p>

</body>
</html>

Hello World!

This text and viewport will resize with the device width.

Breaking the attribute down:

  • width=device-width — sets the page's width to follow the device's own screen width, rather than a fixed desktop value.
  • initial-scale=1.0 — sets the initial zoom level when the page first loads, so the browser doesn't zoom out to fit a wider assumed layout.

Note: This exact meta tag is already sitting in the <head> of every page in this site, including this one — it's part of the shared page template, in the Meta Section block. Every lesson you've worked through so far has had it active the whole time; it's just being explained here now that the CSS Responsive section is the place for it.

Size Content to the Viewport

Users are used to scrolling web pages vertically, not horizontally. If a visitor must scroll sideways, or zoom out, to see the whole page or read a line of text, that's a sign of a poor user experience. A few rules help avoid it:

  • Do not use large fixed-width elements — an image set to a fixed pixel width wider than a narrow phone screen will force horizontal scrolling.
  • Do not let content rely on a particular viewport width to render correctly — a page should work whether the viewport is 300px or 1920px wide.
  • Use CSS media queries to apply different styles for small and large screens, and prefer relative sizing (like width: 100%) over fixed pixel widths wherever an element's container might shrink.
Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <meta name="viewport" content="width=device-width, initial-scale=1.0">
     <style>
         .responsive-box {
             width: 100%;
             max-width: 600px;
             background-color: dodgerblue;
             color: white;
             padding: 20px;
             box-sizing: border-box;
         }
         .fixed-box {
             width: 800px;
             background-color: tomato;
             color: white;
             padding: 20px;
         }
     </style>
</head>
<body>

     <h3>width: 100% with max-width</h3>
     <div class="responsive-box">This box shrinks and grows with its container, but never exceeds 600px.</div>

     <h3>A fixed pixel width</h3>
     <div class="fixed-box">This box stays 800px wide no matter what, forcing horizontal scroll on narrow screens.</div>

</body>
</html>

A fixed pixel width
