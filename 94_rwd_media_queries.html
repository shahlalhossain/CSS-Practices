RWD Media Queries

The general @media syntax was already introduced back in CSS Media Queries. This lesson is the RWD-specific follow-up: applying that same @media rule specifically to solve responsive layout problems — rearranging page regions at a breakpoint, targeting standard device-width tiers, reacting to screen orientation, hiding elements on small screens, scaling text, and respecting a user's reduced-motion preference. All 7 examples below use a real, working @media rule; since each one reads the actual browser viewport rather than a table cell, every demo is shown simulated inside a fixed-width wrapper so both states are visible at once without resizing the browser (the same approach used in CSS Media Queries, Flexbox Responsive, and RWD Intro).

1. Use a Media Query to Add a Breakpoint

A single breakpoint at 768px rearranges a header/menu/main/footer layout from a stacked single column into a two-column layout with a side menu, using grid-template-areas:

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         .grid-container {
             display: grid;
             grid-template-areas:
                 "header"
                 "menu"
                 "main"
                 "footer";
         }

         @media only screen and (min-width: 768px) {
             .grid-container {
                 grid-template-columns: 1fr 3fr;
                 grid-template-areas:
                     "header header"
                     "menu main"
                     "footer footer";
             }
         }
     </style>
</head>
<body>

     <div class="grid-container">
         <div style="grid-area: header;">Header</div>
         <div style="grid-area: menu;">Menu</div>
         <div style="grid-area: main;">Main</div>
         <div style="grid-area: footer;">Footer</div>
     </div>

</body>
</html>

2. Another Breakpoint

Real pages usually need more than one breakpoint. Adding a second @media rule at a wider point lets a layout pass through a third, even-more-spacious arrangement once there's enough room for it — for example, growing the menu column again once the viewport passes 992px, on top of the 768px breakpoint from Example 1.

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         .menu, .main { padding: 14px; color: #fff; text-align: center; border-radius: 4px; }
         .menu { background: dodgerblue; }
         .main { background: #555; }
         .wrapper { display: grid; grid-template-columns: 1fr; gap: 8px; }

         @media only screen and (min-width: 600px) {
             .wrapper { grid-template-columns: 1fr 2fr; }
         }
         @media only screen and (min-width: 768px) {
             .wrapper { grid-template-columns: 1fr 3fr; }
         }
         @media only screen and (min-width: 992px) {
             .wrapper { grid-template-columns: 1fr 4fr; }
         }
     </style>
</head>
<body>

     <div class="wrapper">
         <div class="menu">Menu</div>
         <div class="main">Main Content</div>
     </div>

</body>
</html>

Narrow (< 600px) — stacked:

Menu
Main Content

Desktop (>= 992px) — menu column 1/5 of the width:

Menu

3. Typical Device Breakpoints

There's no single "correct" set of breakpoints — they should fit the content, not a specific device. That said, a commonly used starting set of five breakpoints covers most phones, tablets, and desktops:

Breakpoint Typical Device
max-width: 575.98pxExtra small devices (portrait phones)
min-width: 576pxSmall devices (landscape phones)
min-width: 768pxMedium devices (tablets)
min-width: 992pxLarge devices (desktops)
min-width: 1200pxExtra large devices (large desktops)

Note: This matches the breakpoint scheme used by several real frameworks (Bootstrap among them, in spirit) — but treat these as a reasonable default, not a hard rule. A page with very wide content might need its own breakpoint somewhere in between.

4. Media Queries for Screen Orientation

The orientation media feature targets whether the viewport is currently taller than it is wide (portrait) or wider than it is tall (landscape) — useful for phones and tablets, which can be rotated at any time.

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         body { background-color: tomato; }

         @media only screen and (orientation: landscape) {
             body { background-color: dodgerblue; }
         }
     </style>
</head>
<body>

     <h2>Resize the browser window.</h2>
     <p>If the height is greater than the width, the background color is tomato. If the width is greater than the height (landscape), the background color is dodgerblue.</p>

</body>
</html>

Portrait (height > width):

tomato background

Landscape (width > height):

dodgerblue background

Note: On a desktop browser, rotate the device isn't possible, so this is normally tested on an actual phone/tablet, or by making the browser window taller than it is wide versus wider than it is tall.

5. Hide Elements With Media Queries

Another common responsive technique is simply removing an element from small screens entirely with display: none inside a media query — often used for secondary content, decorative images, or a sidebar that doesn't fit on a phone:

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         @media only screen and (max-width: 600px) {
             div.hideable {
                 display: none;
             }
         }
     </style>
</head>
<body>

     <h2>Resize the browser window</h2>
     <p>This paragraph is always visible.</p>
     <div class="hideable">This div disappears at 600px or narrower.</div>

</body>
</html>

Wide (> 600px) — both visible:

This paragraph is always visible.

This div disappears at 600px or narrower.

Narrow (≤ 600px) — the orange div is gone:

This paragraph is always visible.

This div disappears at 600px or narrower.

6. Change Font Size With Media Queries

Media queries can also scale typography, growing headline text on larger screens where there's room for it, instead of leaving a tiny phone-sized heading stretched across a wide desktop viewport:

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         h1.title { font-size: 20px; }

         @media screen and (min-width: 600px) {
             h1.title { font-size: 50px; }
         }
     </style>
</head>
<body>

     <h1 class="title">Hello World</h1>
     <p>Resize the browser window to see the effect.</p>

</body>
</html>

Below 600px:

7. Media Queries for User Preferences

Not every media query is about screen size. The prefers-reduced-motion feature detects a system-level accessibility setting some users turn on to avoid animation-triggered discomfort (motion sickness, vestibular disorders); respecting it means disabling non-essential animations and transitions when it's set to reduce:

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         .ball {
             width: 40px; height: 40px; border-radius: 50%;
             background: dodgerblue;
             animation: bounce 1s infinite alternate;
         }

         @keyframes bounce {
             from { transform: translateX(0); }
             to { transform: translateX(200px); }
         }

         @media (prefers-reduced-motion: reduce) {
             .ball { animation: none; }
         }
     </style>
</head>
<body>

     <div class="ball"></div>

</body>
</html>

Default (motion allowed) — the ball actually animates back and forth:

Simulated with prefers-reduced-motion: reduce set — animation is removed, ball sits still:

Note: The @media (prefers-reduced-motion: reduce) rule above is real and will actually disable the first ball's animation too if your own OS/browser has that accessibility setting turned on — the second ball is a simulated "reduced" state added here so the contrast is visible regardless of your system setting.
