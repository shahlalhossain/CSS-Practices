The CSS !important Rule

The !important rule gives a single property declaration the highest priority available in CSS. Adding it after a value — before the semicolon — makes that declaration override ALL previous styling rules for that specific property on that element, no matter how specific the competing selector is.

Syntax: selector { property: value !important; }

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         p { background-color: yellow !important; }
         #myid { background-color: blue; }
         .myclass { background-color: gray; }
     </style>
</head>
<body>

     <h2>Using the !important Rule</h2>
     <p style="background-color:orange;">This is a paragraph.</p>
     <p class="myclass">This is a paragraph.</p>
     <p id="myid">This is a paragraph.</p>

</body>
</html>

Note: Without !important, the first paragraph's inline style, the second's class, and the third's ID would each win their own specificity battle and show three different colors. Because the p rule alone carries !important, all three paragraphs turn yellow instead — !important overrides even an inline style and an ID.

Important Rules Should Be Used With Caution

If multiple conflicting declarations for the same property on the same element all carry !important, the declaration with the highest specificity among them wins. So !important doesn't remove specificity from the equation entirely — it just raises the whole contest onto a higher tier.

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         p {
             background-color: red !important;
         }

         #myid {
             background-color: blue !important;
         }

         .myclass {
             background-color: gray !important;
         }
     </style>
</head>
<body>

     <h2>Confusing !important Rules</h2>
     <p>This is a paragraph.</p>
     <p class="myclass">This is a paragraph.</p>
     <p id="myid">This is a paragraph.</p>

</body>
</html>

Confusing !important Rules

This is a paragraph.

This is a paragraph.

This is a paragraph.

Note: Here, every rule is marked !important, so normal specificity rules apply among them: the ID (#myid, highest specificity) wins blue, the class (.myclass) wins gray, and the plain element rule (p) is left with the one paragraph that has neither a class nor an ID, showing red. Stacking !important everywhere just pushes the specificity war up a level — it doesn't make styling any easier to reason about, which is exactly why the rule should be used sparingly.

Overriding a More Specific Rule

A common real-world use is forcing a reusable utility class (like a button style) to hold its look even inside a container that has its own, more specific override. Without !important, the more specific #myDiv a rule below beats the a.button rule on the second link, even though a.button is declared first.

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         a.button {
             background-color: #8c8c8c;
             color: white;
             padding: 5px;
             border: 1px solid black;
             text-decoration: none;
         }

         #myDiv a {
             color: red;
             background-color: yellow;
         }
     </style>
</head>
<body>

     <p>Standard link button: <a class="button" href="#">CSS Tutorial</a></p>

     <div id="myDiv">
         <p>A link text inside #myDiv: <a href="#">HTML Tutorial</a></p>
         <p>A link button inside #myDiv: <a href="#" class="button">HTML Tutorial</a></p>
     </div>

</body>
</html>

Notice the second button, nested inside #myDiv, loses its gray/white button look: #myDiv a (0-1-1 with the ID) outranks a.button (0-1-1 with one element and one class — same weight, but #myDiv a was declared later). Adding !important to every property in a.button forces it to win back control over both links, regardless of where they're nested:

Example Code Sample Output
<!DOCTYPE html>
<html>
<head>
     <style>
         a.button {
             background-color: #8c8c8c !important;
             color: white !important;
             padding: 5px !important;
             border: 1px solid black !important;
             text-decoration: none !important;
         }

         #myDiv a {
             color: red;
             background-color: yellow;
         }
     </style>
</head>
<body>

     <p>Standard link button: <a class="button" href="#">CSS Tutorial</a></p>

     <div id="myDiv">
         <p>A link text inside #myDiv: <a href="#">HTML Tutorial</a></p>
         <p>A link button inside #myDiv: <a href="#" class="button">HTML Tutorial</a></p>
     </div>

</body>
</html>

Standard link button: CSS Tutorial

A link text inside #myDiv: HTML Tutorial

A link button inside #myDiv: HTML Tutorial

Note: Both buttons now render identically, gray with white text, since !important on a.button beats the plain #myDiv a rule regardless of its higher normal specificity. This is a legitimate, narrow use case — forcing a component's own style to hold up inside unpredictable surrounding markup — but reach for it only after normal specificity and source order can't solve the problem, since overusing !important makes a stylesheet much harder to debug and maintain.
